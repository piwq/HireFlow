02 Контекст

Почему классический найм буксует

HR-команды собирают процесс из разрозненных инструментов — каждый из них теряет контекст на стыке.

01

Разрозненность

Excel для учёта, почта для писем, Zoom для интервью. Данные не сшиты, контекст теряется на стыке.

  • Нет единого профиля кандидата
  • HR переключает 4–6 вкладок за день
  • Статус кандидата — только в голове
→ HireFlow: единое окно с ролевой моделью, Kanban, чатом и LiveKit
02

Ручной ввод

Опыт работы, сертификаты, справки — заполняются руками часами. Кандидаты бросают формы.

  • Форма резюме — 20+ полей вручную
  • Конверсия падает на каждом шаге
  • Ошибки при ручном переносе из документов
→ HireFlow: импорт выписки СТД-Р за 10 секунд + AI-конструктор резюме
03

Потеря истории

Кто и когда менял статус, какие были отзывы, кто видел резюме — вопросы без ответов.

  • Решения принимаются по памяти, не по данным
  • При увольнении HR — история теряется
  • Нет полного контекста при повторном найме
→ HireFlow: audit log, история статусов с авторами и датами, notes
04

Молчание

Кандидат неделями не знает результата. HR забывает ответить. HR-бренд страдает.

  • Отказ без ответа — топ жалоб кандидатов
  • HR-бренд падает → дороже привлекать людей
  • Ручные письма — непоследовательны и медленны
→ HireFlow: WebSocket + Telegram: мгновенные уведомления всем сторонам
03 Концепция

HireFlow — единая платформа

Один продукт закрывает весь цикл: от регистрации кандидата до оффера. Четыре принципа, которые отличают HireFlow от «очередной CRM».

RBAC

Чёткие права

Четыре роли, жёсткая ролевая модель, IDOR-защита на уровне запросов.

  • require_role() декоратором на каждом роуте
  • IDOR-фильтр через SQL JOIN по manager_id
  • JWT в заголовке Authorization, не в cookie
  • Блокировка через is_active = false
RT

Real-time

WebSocket + Telegram-бот. Kanban обновляется без F5, уведомления — мгновенно.

  • WebSocket-соединение на каждого пользователя
  • Единый notifications.py — один вызов → WS + TG
  • Kanban drag-and-drop синхронизирует всех HR
  • История переходов: кто, когда, из какой стадии
AI

AI-ассистент

Gemini генерирует резюме и парсит выписку с Госуслуг — без галлюцинаций.

  • Multi-model fallback: 2.5-flash → 1.5-flash → 1.5-pro
  • Потоковый SSE-ответ (streaming), не ждёшь финала
  • pdfplumber парсит таблицы СТД-Р за ~10 сек
  • DOMPurify санитизирует AI-вывод от XSS
LK

Встроенное видео

Интервью через LiveKit прямо в карточке — без Zoom и Teams.

  • Self-hosted LiveKit в Docker-сети, данные не уходят
  • Токен выдаёт backend через /api/livekit
  • WebRTC peer-to-peer, UDP 50100–50200
  • Видеозвонок стартует из карточки кандидата

18 Безопасность · ТЗ 5.2

Hardening: что защитили

Все требования из раздела 5.2 ТЗ закрыты. Плюс несколько слоёв сверху.

✓

SQL Injection

SQLAlchemy ORM везде — параметризованные запросы, raw SQL отсутствует.

✓

XSS

DOMPurify.sanitize на весь AI-вывод и пользовательский контент. Vue экранирует по умолчанию.

✓

CSRF

JWT в Authorization-заголовке, не в cookie. Attack surface минимален.

✓

IDOR

Менеджер видит только своих кандидатов через JOIN по интервью. Фильтр на уровне БД.

✓

RBAC

require_role(...) на каждом чувствительном роуте FastAPI.

✓

Password hashing

bcrypt с per-user salt. Блокировка аккаунта через is_active.

✓

Security headers

CSP, HSTS, X-Frame-Options, X-Content-Type-Options в middleware.

✓

File upload

Whitelist mime-типов и расширений. Хранение в MinIO с привязкой к владельцу.

✓

JWT expiration

Токен с TTL, ревокация через блокировку аккаунта и смену пароля.
