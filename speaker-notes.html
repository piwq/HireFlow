02Проблема

Почему классический найм буксует

⏱ 40 сек
🗣Что сказать

Современный найм собран из разрозненных инструментов: Excel, почта, Zoom, Google-формы. На каждом стыке теряется контекст.

Четыре боли: разрозненность, ручной ввод, потеря истории, молчание по кандидату. Каждую закрываем одним продуктом.

🎯Карта «проблема → решение»
  • Разрозненность → единое окно с Kanban, чатом, LiveKit
  • Ручной ввод → импорт СТД-Р + AI-конструктор резюме
  • Потеря истории → audit log, история статусов, notes
  • Молчание → WebSocket + Telegram-бот, мгновенно

05Стек

Стек разработки

⏱ 30 сек · не перечисляй всё — выделяй
🗣Что сказать

Современный асинхронный стек: Vue 3 + Pinia на фронте, FastAPI + async SQLAlchemy на бэке. Всё поднимается одной командой docker compose up.

Из нестандартного: LiveKit для видео, MinIO как S3, Gemini с multi-model fallback.

⚠️Если спросят «почему»
Почему FastAPI, а не Django?
Async-first, нативная поддержка WebSocket, автогенерация OpenAPI, меньше оверхеда под API-only бэк.
Почему MinIO, а не S3?
Self-hosted в docker-сети, API-совместимо с S3 — легко мигрировать в облако без изменений кода.
06Архитектура

Как это собрано

⏱ 60 сек · самый важный слайд для «технарей»
🗣Что сказать

SPA на Vue ходит в stateless FastAPI по HTTPS и WebSocket. Бэкенд — без сессий, JWT в заголовке Authorization.

Middleware-цепочка: CORS → Security headers → JWT → require_role → Handler. Service-слой отделён от роутеров: notifications, s3, telegram_bot, ai fallback, pdf-parser.

Миграции через Alembic, сиды через seed.py — 15 пользователей, 6 вакансий, 14 откликов.

🗂️Что где искать
  • backend/app/routers/ — endpoints, 15 модулей
  • backend/app/services/ — AI, S3, Telegram, notifications
  • backend/app/deps.py — get_current_user, require_role

11Сценарий · Руководитель

Руководитель в найме

⏱ 30 сек
🗣Что сказать

Руководитель видит только своих кандидатов — фильтр в БД через JOIN по назначенным интервью. Защита от IDOR не на фронте, а на уровне запроса.

Фильтрация в самом SQL-запросе по manager_id через JOIN с интервью. Даже если подделать ID в URL — SELECT не вернёт строку.

16Killer · LiveKit + TG

LiveKit и Telegram Synergy

⏱ 40 сек
🗣Что сказать

LiveKit крутится в нашей Docker-сети, токен выпускает бэкенд — никаких Zoom и Teams. Интервью стартует прямо из карточки кандидата.

Telegram-бот — единая шина уведомлений: один вызов notifications-сервиса рассылает и в WebSocket, и в TG. HR получает пуш «кандидат подтвердил интервью», кандидат — «вам назначено собеседование».

⚠️Возможный вопрос
Почему свой LiveKit, а не Zoom SDK?
Self-hosted WebRTC — данные не уходят во внешние сервисы. Важно для HR-контекста: персональные данные, оценки.
17Безопасность

Hardening: что защитили

⏱ 45 сек · любимый вопрос жюри
🗣Что сказать

Закрыт весь чек-лист раздела 5.2 ТЗ. SQLi — только ORM, raw SQL отсутствует. XSS — Vue эскейпит по умолчанию + DOMPurify на AI-выводе. CSRF — JWT в заголовке, не в cookie. IDOR — фильтры в БД-запросе.

Сверху: CSP, HSTS, X-Frame-Options, X-Content-Type-Options через middleware. Пароли — bcrypt с per-user salt.

🛡️Матрица угроз
SQLi ✓ XSS ✓ CSRF ✓ IDOR ✓ RBAC ✓ Headers ✓ bcrypt ✓

Q&AБонус

Топ-5 сложных вопросов

1. Что будет при отказе Gemini API?
Multi-model fallback: 2.5-flash → 1.5-flash → 1.5-pro → pro. Если все упали — UI показывает ошибку, кандидат заполняет руками. Сервис не падает.
2. Как масштабировать WebSocket?
Сейчас in-memory registry подключений. На horizontal scale — Redis pub/sub, уже в roadmap. Бэкенд stateless, упирается только в sockets.
3. Как тестируете?
На хакатоне приоритет был на функционал. Честно: покрытие pytest в roadmap 80%+. Архитектура с service-слоем позволяет легко добавить юнит-тесты.
4. Почему не использовали готовые ATS?
ТЗ требовало собственное решение. Плюс готовые ATS не умеют работать с СТД-Р и российской спецификой — нам пришлось бы всё равно писать парсер.
5. Что если кандидат без Telegram?
Уведомления идут и в WebSocket (внутри приложения), и в Telegram — дубликат. Telegram — опционально, привязка через бота в настройках.
